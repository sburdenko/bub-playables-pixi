# Bubble Playable (PixiJS)

Рекламный playable bubble shooter на TypeScript + PixiJS v8. Результат сборки — **один `index.html`** для рекламных сетей.

## Быстрый старт

> Арт и шрифт (`assets-src/`) принадлежат третьим лицам и в репозиторий не входят. Без этой папки код можно читать, но собрать игру нельзя.

```bash
npm install
```

```bash
npm run assets:build
```

```bash
npm run dev
```

- Игра: <http://localhost:5173>
- Галерея всех спрайтов (только dev): <http://localhost:5173/dev/assets.html>
- С телефона в той же Wi-Fi сети: адрес `Network:` из вывода `npm run dev`.

В dev-сборке приложение доступно расширению **PixiJS DevTools** для Chrome (дерево сцены, свойства объектов).

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер с мгновенной перезагрузкой |
| `npm run assets:build` | `assets-src/` → атласы, сжатие, `src/generated/assets.ts` |
| `npm run build` | typecheck + сборка в один `dist/index.html` |
| `npm run verify` | всё сразу: ассеты, lint, typecheck, unit + покрытие, сборка, размер, e2e |
| `npm run test` / `test:watch` | unit-тесты (Vitest) |
| `npm run coverage` | unit-тесты с порогом покрытия 80% |
| `npm run e2e` | e2e-тесты собранного билда в Chrome (Playwright) |
| `npm run size` | проверка: один файл и не больше 4.5 МБ |

## Как устроен код

Пять слоёв, зависимости только вниз (проверяет ESLint, правило `layers/dependency-direction`):

```
app (сборка всего) ─┬─ view (PixiJS) ──────┐
                    └─ platform (браузер) ─┤ реализуют порты из game/ports
                                game ──────┘  сценарий хода
                                domain        правила игры, чистые функции
                                core          математика, утилиты
```

| Папка | Что внутри |
|---|---|
| `src/core`, `src/domain`, `src/game` | логика без PixiJS и без DOM; покрыта unit-тестами |
| `src/view` | всё, что рисует; зависит только от портов `game/ports` |
| `src/platform` | экран, касания, загрузка ассетов, рекламный SDK |
| `src/app` | composition root (`Bootstrap.ts`), конфиг |
| `src/dev` | dev-страницы, в продакшен-сборку не попадают |
| `src/generated` | генерируется `npm run assets:build`, не редактировать и не коммитить |
| `assets-src/` | исходные картинки и шрифт + `catalog.json` |
| `tools/` | сборка ассетов, проверка размера, правило ESLint |

## Ассеты

Источник — `assets-src/`. **Папка, в которой лежит картинка, — это её группа**, а группа решает, как картинка попадёт в игру. Правила групп лежат в [tools/assets/rules.ts](tools/assets/rules.ts):

| Папка | Куда идёт | Масштаб | Формат |
|---|---|---|---|
| `hero/`, `enemy/` | свой атлас, обрезка прозрачных полей | 0.4 | WebP |
| `bubbles/` | атлас, обрезка прозрачных полей | 0.5 (тела, тень, обводка — 0.4) | WebP |
| `ui/` | атлас | 1 (нижняя панель — 0.5) | WebP |
| `frame/`, `vfx/` | свои атласы | 0.45 / 1 | PNG с палитрой |
| `single/` | отдельный файл | 1 | JPEG |

**Добавить картинку:**
1. Положите PNG в нужную папку `assets-src/<группа>/`.
2. Добавьте запись в `assets-src/catalog.json`: `id`, `file`, `width`, `height`, `pixelsPerUnit`, `anchor`, `borders`.
3. `npm run assets:build`, и картинка доступна в коде по `id`.

Папка без правила ломает сборку: решение «что и как везём» всегда явное. `pixelsPerUnit` пересчитывается при уменьшении, поэтому размер на экране не меняется.

## Конвенции

- `interface` с префиксом `I` описывает поведение (контракт), `type` описывает данные.
- Приватные поля `_camelCase`, константы `UPPER_SNAKE_CASE`, булевы значения начинаются с `is` / `has` / `can`.
- Без глобального состояния и синглтонов, всё передаётся через конструктор.
- Комментарии только для публичных контрактов и неочевидного «почему».
